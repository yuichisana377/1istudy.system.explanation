# `/quiz_create` とクイズ過去問ランキング（`bot.py` 5129〜5321行）

対象：`bot.py`の`/quiz_create`、および「クイズ過去問（CardMaker内の一人用4択モード）のランキング」セクション。

## 1. `/quiz_create`：ルームの作成（5129〜5216行）

- `title = str(data.get("title") or "").strip()[:40] or "みんなでクイズ"`… タイトルは最大40文字に切り詰め、空なら`"みんなでクイズ"`というデフォルト名になります。
- `source`（クイズの元になる出題方法）が`"deck"`か`"manual"`かで、[01_ルーム状態のJSON化と問題の自動生成.md](01_ルーム状態のJSON化と問題の自動生成.md)で見た`_build_deck_questions`（デッキから自動生成）か`_validate_manual_questions`（ホストの手入力を検証）のどちらかに分岐します。それ以外の値は`"invalid_source"`として拒否します。
- `deck_filenames`の後方互換処理：`if not deck_filenames: single = data.get("deck_filename"); deck_filenames = [single] if single else None`… 複数デッキ選択に対応する前は、単一の`deck_filename`という名前のフィールドしかありませんでした。新しいフィールド（`deck_filenames`）が無ければ、古いフィールド（`deck_filename`）を1要素のリストとして使う、というフォールバックです。フロント側が新しい形式に完全移行していなくても、古い呼び出し方のままでも動き続けます。
- どちらの`source`でも、最終的に`reject_if_bug_chars`で不正文字チェックが行われます。`manual`の場合はタイトルだけでなく、[01_ルーム状態のJSON化と問題の自動生成.md](01_ルーム状態のJSON化と問題の自動生成.md)の`_validate_manual_questions`が作った`check_fields`（各問題・各選択肢のテキスト全部）もまとめてチェックされます。

## 2. クイズ過去問ランキング（5218〜5321行）

コメントにある通り、これは進行中のライブルーム（`QUIZ_ROOMS`、メモリ上のみ）とは異なる、**ディスクに永続化される**仕組みです。「クイズ過去問」フォルダにアーカイブされたデッキ1つにつき1ファイル（`quiz_leaderboard_<デッキのfilename>.json`）に、各生徒のベストスコアだけを保持します。

```python
def _is_safe_deck_filename(filename):
    return bool(filename) and filename.endswith(".json") \
        and "/" not in filename and "\\" not in filename and ".." not in filename
```
- これまで何度も個別に書かれていたパストラバーサル対策のチェック（`"/" not in filename`等）が、ここで初めて**専用の関数として切り出されて**います。加えて、`.endswith(".json")`という新しいチェックも追加されており、これまでの類似チェックより一段階厳しくなっています。

```python
def _update_quiz_leaderboard(deck_filename, mutate_fn, max_attempts=4):
    """mutate_fn(leaderboard_dict) は dict を直接書き換える関数。
    保存に失敗（sha競合）した場合は最新データを読み直して再適用する。"""
    lb_filename = f"quiz_leaderboard_{deck_filename}"
    last_err = None
    for _ in range(max_attempts):
        data, sha = local_get(lb_filename)
        data = data or {}
        mutate_fn(data)
        try:
            local_put(lb_filename, data, sha)
            return
        except DataWriteError as e:
            last_err = e
            continue
    raise last_err or DataWriteError("保存に失敗しました（リトライ上限）")
```
- これは、これまでの回で見た「1回だけ無条件リトライする」`local_put`よりも**もう一段階丁寧な**楽観的排他制御のパターンです。`mutate_fn`（呼び出し元が渡す「データをどう書き換えるか」の関数）を、**最新のデータを読み直すたびに何度でも適用し直す**ことで、他の誰かが先に保存していた場合でも、最大4回まで「読み直す→書き換える→保存を試みる」を繰り返します。[../02_データ保存基盤/00_ファイル読み書きとSHA排他制御.md](../02_データ保存基盤/00_ファイル読み書きとSHA排他制御.md)の`local_put`の「無条件で1回だけ上書き」よりも、こちらの方が理論的により安全です（同時に複数人がスコアを送信しても、互いの記録を取りこぼしにくくなります）。ランキングという「複数人が同時に触りやすいデータ」だからこそ、より丁寧な排他制御が採用されていると考えられます。

```python
@app.route("/quiz_archive_submit_score", methods=["POST"])
def quiz_archive_submit_score():
    """一人用4択モードのスコアを記録する。ベストスコアだけを保持する。"""
    data = request.json or {}
    guild_id = data.get("guild_id")
    if not guild_id:
        return jsonify({"ok": False, "error": "missing guild_id"})
    guild_id = int(guild_id)
    student_id, err = require_member_session(data.get("session_token"), guild_id)
    if err:
        return err

    filename = data.get("filename") or ""
    if not _is_safe_deck_filename(filename):
        return jsonify({"ok": False, "error": "invalid filename"})

    try:
        score = int(data.get("score"))
        total = int(data.get("total"))
    except (TypeError, ValueError):
        return jsonify({"ok": False, "error": "invalid score/total"})
    if score < 0 or total <= 0 or score > total:
        return jsonify({"ok": False, "error": "invalid score/total"})

    card_data, _ = get_card_file(filename)
    if card_data is None:
        return jsonify({"ok": False, "error": "deck_not_found"})
    if not card_data.get("choice_mode"):
        return jsonify({"ok": False, "error": "not_a_choice_deck"})
```
- `if score < 0 or total <= 0 or score > total:`… スコアが物理的にありえない値（マイナスの点数、正解数が全体の問題数を超えるなど）でないかを検証します。
- コメントの通り、「このデッキが実際に『クイズ過去問』フォルダの中にあるか確認する（でたらめなfilenameを指定してスコアを偽造されるのを防ぐ）」という検証がありますが、判定方法が変更された経緯も記録されています：「以前は『クイズ過去問フォルダ内かどうか』で判定していたが、選択式デッキが汎用機能になったため、`choice_mode`の有無で判定するよう変更」。当初はクイズ過去問専用の機能として作られましたが、選択式デッキという概念自体がCardMakerの一般機能に昇格したため、「特定のフォルダに入っているか」ではなく「選択式デッキであるかどうか」という、より本質的な条件でチェックするように改められています。`choice_mode`のtruthyチェック（`not card_data.get("choice_mode")`）は、新形式の`True`だけでなく、移行前の旧形式（文字列`"single"`/`"multi"`）も引き続き通すためです。

- `_mutate`関数を、その場で（`_update_quiz_leaderboard`の引数として渡すためだけに）定義しています。中身は「既存の記録が無いか、今回のスコアの方が高ければ、記録を上書きする」という**ベストスコアだけを残す**ロジックです。何度挑戦しても、一番良かった記録だけがランキングに反映されます。

```python
@app.route("/quiz_archive_leaderboard", methods=["GET"])
def quiz_archive_leaderboard():
    """指定デッキ（クイズ過去問）のランキングをスコア降順で返す。"""
    filename = request.args.get("filename") or ""
    if not _is_safe_deck_filename(filename):
        return jsonify({"ok": False, "error": "invalid filename"})
    data, _ = local_get(f"quiz_leaderboard_{filename}")
    data = data or {}
    rows = [
        {"student_id": sid, "nickname": e.get("nickname"), "score": e.get("score"), "total": e.get("total"), "played_at": e.get("played_at")}
        for sid, e in data.items()
    ]
    rows.sort(key=lambda r: (-(r["score"] or 0), r["played_at"] or ""))
    return jsonify({"ok": True, "leaderboard": rows})
```
- `rows.sort(key=lambda r: (-(r["score"] or 0), r["played_at"] or ""))`… **タプルによる複合ソート**です。Pythonのソートは、タプルを比較する際に「1つ目の要素で比較し、同点なら2つ目の要素で比較する」という動きをします。ここでは、まずスコアの降順（マイナスを付けて反転）で並べ、**同点だった場合は`played_at`（挑戦日時）の昇順**で並べます。つまり「同じ点数なら、先に達成した人が上位に来る」という、早い者勝ちのタイブレークルールです。
