# 勉強タイマーの状態管理（`bot.py` 749〜1042行）

対象：`bot.py`の「勉強タイマー状態（複数端末で共有）」セクション。[[../../1I勉強会web解説/04_StudyLog/00_HTML構造とページ全体像.md]]で見た「勉強タイマー」機能の、サーバー側の実装です。

## なぜサーバー側で時刻管理しているのか（コメントより）

以前はブラウザの`localStorage`（そのブラウザだけに保存される、端末専用の保存領域）にタイマーの開始時刻を保存していました。これには2つの問題がありました。
1. 別端末・別ブラウザで開いても状態が見えず、うっかり二重に計測を始められてしまう。
2. タブを閉じる、またはバックグラウンドに置くとJavaScriptの実行が止まるため、「3時間経過したら自動的に休憩にする」という判定がブラウザの復帰まで遅れてしまう（精度が低い）。

これを解決するため、**開始・一時停止・再開の「時刻」そのものをサーバー側（ローカルディスク）で管理**する方式に変えています。どの端末で開いても同じ状態が見え、3時間経過の判定やDM通知も、クライアントのタブが開いているかどうかに関係なく、サーバー側の定期ジョブ（`check_study_timers`。後の回で解説）によって正確に行われます。

## データの形（コメントより）

`study_timers_{guild_id}.json`の中身は`{学籍番号: エントリ, ...}`という辞書です。1件のエントリは次のフィールドを持ちます。
- `state`… `"running"`（計測中）か`"paused"`（一時停止中）。
- `run_start_epoch`… 現在の計測区間が始まった時刻（ミリ秒単位のUnix時間。`running`のときだけ値がある）。
- `accumulated_sec`… **直近の計測区間を含まない**、これまでの累計秒数。
- `next_checkpoint_sec`… 次に「3時間経過」の自動休憩を入れる、累計秒数のライン。
- `pause_reason`… `"manual"`（自分で休憩ボタンを押した）か`"checkpoint"`（3時間経過による自動休憩）。

```python
TIMER_CHECKPOINT_SEC = 10800  # 3時間ごとに自動的に休憩へ切り替える
```
- `10800`秒 = 3時間です。長時間つけっぱなしにして不正確な記録になるのを防ぐための仕組みです。

## 2. 経過時間の計算方法

このファイルには「経過秒数」そのものは保存されていません。代わりに「区間が始まった時刻（`run_start_epoch`）」と「それより前の累計（`accumulated_sec`）」だけを保存し、**必要になるたびに「今の時刻 − 開始時刻」を計算して足す**、という設計になっています。これにより、サーバーが何もしなくても、時間が経てば経つほど自動的に経過時間が伸びていく（=「今何秒経過しているか」を毎回問い合わせなくても正しく計算できる）ようになっています。

## 3. 3時間経過の自動休憩判定：`_finalize_study_timer`（797〜830行）

```python
def _finalize_study_timer(entry, now_ms):
    if not entry:
        return None, None

    state = entry.get("state")

    if state == "running":
        run_start = entry.get("run_start_epoch")
        accumulated = entry.get("accumulated_sec", 0) or 0
        if run_start is not None:
            elapsed = accumulated + (now_ms - run_start) / 1000.0
        else:
            elapsed = accumulated
        checkpoint = entry.get("next_checkpoint_sec", TIMER_CHECKPOINT_SEC) or TIMER_CHECKPOINT_SEC
        if elapsed >= checkpoint:
            new_entry = dict(entry)
            new_entry["accumulated_sec"] = int(round(elapsed))
            new_entry["run_start_epoch"] = None
            new_entry["state"] = "paused"
            new_entry["pause_reason"] = "checkpoint"
            new_entry["next_checkpoint_sec"] = checkpoint + TIMER_CHECKPOINT_SEC
            return new_entry, "auto_paused"
        return entry, None

    return entry, None
```
- コメントにある通り「副作用なしの純粋関数」です。純粋関数とは、渡された引数だけから結果を計算し、外部の状態（ファイルなど）を一切書き換えない関数のことです。実際に保存するかどうかの判断は、この関数を呼び出す側に委ねられています。
- `state`が`"running"`のときだけ判定が行われます。今の経過時間`elapsed`（`accumulated`に、今の区間の分＝`(now_ms - run_start) / 1000.0`を足したもの）が、次のチェックポイント`checkpoint`に達していれば、状態を`"paused"`に切り替えた新しいエントリ`new_entry`を作って返します。このとき`pause_reason`は`"checkpoint"`（自動休憩）になります。
- `new_entry["next_checkpoint_sec"] = checkpoint + TIMER_CHECKPOINT_SEC`… 次にまた3時間経過したときのために、次回のチェックポイントのラインをさらに3時間先に進めておきます。これにより、再開してさらに3時間動かせば、また同じように自動休憩が挟まれます。
- 戻り値は`(新しいエントリ or 元のエントリそのまま, 通知の種類)`という2つ組（タプル）です。変化が無ければ`entry`をそのまま返し、通知の種類は`None`のままです。

```python
def _try_notify_timer(guild_id, student_id, message):
    try:
        send_discord_dm(guild_id, student_id, "StudyLog", message)
    except Exception as e:
        print(f"[WARN] study_timer DM通知に失敗しました（student_id={student_id}）: {e}")
```
- コメントの通り「通知はベストエフォート（best effort、できる範囲で頑張るが失敗しても許容する）」という位置づけです。DM送信に失敗しても、タイマーの状態遷移自体（一時停止に切り替わったこと）は既に成立しているので、通知の失敗だけを`print`でログに残し、処理全体は止めません。

## 4. 各APIから最初に呼ばれる同期処理：`_sync_timer_entry`（839〜864行）

```python
def _sync_timer_entry(guild_id, student_id):
    timers = load_study_timers(guild_id)
    now_ms = int(time.time() * 1000)
    entry = timers.get(student_id)
    new_entry, notify_kind = _finalize_study_timer(entry, now_ms)

    if new_entry != entry:
        if new_entry is None:
            timers.pop(student_id, None)
        else:
            timers[student_id] = new_entry
        try:
            save_study_timers(guild_id, timers)
            if notify_kind == "auto_paused":
                _try_notify_timer(guild_id, student_id, MSG_TIMER_AUTO_PAUSED)
        except DataWriteError as e:
            print(f"[WARN] study_timers 保存に失敗しました: {e}")

    return timers, new_entry
```
- コメントの通り「どのエンドポイントも、まずこれを呼んでから自分の処理を行う」、いわば全タイマーAPIの入り口の共通処理です。
- 最新のタイマー一覧を読み込み、`_finalize_study_timer`で「3時間経過していないか」を評価します。
- `new_entry != entry`（評価の結果、実際に状態が変わった場合）だけ、改めて保存し直します。変化が無ければ余計な書き込みをしません（無駄なファイルI/Oや、それに伴う`notify_change`の連発を避けています）。
- 保存に成功した場合だけ、`notify_kind == "auto_paused"`なら本人にDM通知します（保存に失敗した場合は通知しません。コメントにある通り「次回アクセス時に再評価される」ため、通知だけが実態と食い違うことはありません）。
- こうして、**タイマー操作用のどのAPI（`timer_state`/`timer_start`/`timer_pause`/`timer_resume`）を呼んでも、最初にこの関数を通ることで、常に最新かつ正しい状態からスタートできる**という設計になっています。

## 5. レスポンス整形：`_timer_entry_json`（866〜884行）

```python
def _timer_entry_json(entry, now_ms=None):
    if now_ms is None:
        now_ms = int(time.time() * 1000)
    if not entry:
        return {"state": "idle", "elapsed_sec": 0, "run_start_epoch": None, "accumulated_sec": 0}
    state = entry.get("state")
    accumulated = entry.get("accumulated_sec", 0) or 0
    run_start = entry.get("run_start_epoch")
    if state == "running" and run_start is not None:
        elapsed = accumulated + (now_ms - run_start) / 1000.0
    else:
        elapsed = accumulated
    return {
        "state": state,
        "elapsed_sec": int(elapsed),
        "run_start_epoch": run_start,
        "accumulated_sec": int(round(accumulated)),
        "pause_reason": entry.get("pause_reason") if state == "paused" else None,
    }
```
- 内部の生のエントリを、フロント側に返すためのJSON形式に整えます。エントリが無ければ`"idle"`（誰も計測していない）を返します。
- `elapsed_sec`（今この瞬間の経過秒数）は、`running`中なら今の区間の分を足して都度計算し直します。`int(elapsed)`で小数点以下を切り捨てています。
- コメントにある通り`accumulated_sec`を`int(round(...))`で整数化しているのは、ミリ秒由来の端数が残ったまま返してしまうと、フロント側の表示が`00:00:16.885`のように小数点付きの見た目になってしまうためです。

## 7. 各エンドポイント（900〜1041行）

```python

    resp = {"ok": True, "server_now": int(time.time() * 1000)}
```

- `/timer_state`… 今の状態を返すだけのGET APIです。`server_now`（サーバー側の現在時刻）も一緒に返しているのは、フロント側がサーバーとの時刻のズレを気にせず、正確な経過時間の表示を計算し続けられるようにするためです。

```python
@app.route("/timer_start", methods=["POST"])
def timer_start():
    timers, entry = _sync_timer_entry(guild_id, student_id)
    now_ms = int(time.time() * 1000)

    if entry is None:
        new_entry = {
            "state": "running", "run_start_epoch": now_ms,
            "accumulated_sec": 0, "next_checkpoint_sec": TIMER_CHECKPOINT_SEC,
        }
        timers[student_id] = new_entry
        ...
        resp = {"ok": True, "created": True}
        ...

    if entry.get("state") == "running":
        resp = {"ok": True, "created": False, "joined": True}
        ...

    resp = {"ok": False, "error": "already_" + str(entry.get("state"))}
    ...
```
- `/timer_start`… コメントにある通り3パターンに分かれます。
  1. 誰も動かしていない（`entry is None`）→ 新規に開始し、`created: True`を返す。
  2. 既に自分（他端末）で計測中（`state == "running"`）→ 新しく作り直さず、**そのまま同じ記録に合流**し、`joined: True`を返す。これにより、同じ人が別のタブ・別のスマホで同時に開いても、二重にタイマーが動くことはありません。
  3. 一時停止中（`paused`）→ 開始せず、`ok: False`とその状態をそのまま返します。フロント側はこのエラーを見て「再開ボタンを出す」のような画面を出し分けます。

```python
@app.route("/timer_pause", methods=["POST"])
def timer_pause():
    ...
    accumulated = int(round((entry.get("accumulated_sec", 0) or 0) + (now_ms - entry["run_start_epoch"]) / 1000.0))
    new_entry = dict(entry)
    new_entry["accumulated_sec"] = accumulated
    new_entry["run_start_epoch"] = None
    new_entry["state"] = "paused"
    new_entry["pause_reason"] = "manual"
    ...
```
- `/timer_pause`… 手動での一時停止です。今までの累計に今の区間の分を足し込んで`accumulated_sec`に確定させ、`run_start_epoch`を`None`に戻します（＝「今計測中の区間」が無くなった状態）。`pause_reason`は`"manual"`（自動休憩の`"checkpoint"`と区別するため）です。

```python
@app.route("/timer_resume", methods=["POST"])
def timer_resume():
    ...
    new_entry = dict(entry)
    new_entry["run_start_epoch"] = now_ms
    new_entry["state"] = "running"
    new_entry.pop("pause_reason", None)
    if "next_checkpoint_sec" not in new_entry:
        new_entry["next_checkpoint_sec"] = (new_entry.get("accumulated_sec", 0) or 0) + TIMER_CHECKPOINT_SEC
    ...
```
- `/timer_resume`… 一時停止から再開です。今の時刻を新しい`run_start_epoch`として書き込み、`state`を`"running"`に戻します。
- `if "next_checkpoint_sec" not in new_entry:`… 古い形式のデータ（この機能ができる前に保存された、`next_checkpoint_sec`フィールドが無いエントリ）との互換性のための処理です。もし無ければ、今の累計から改めて3時間後をチェックポイントとして設定し直します。

```python
@app.route("/timer_stop", methods=["POST"])
def timer_stop():
    ...
    timers = load_study_timers(guild_id)
    if student_id in timers:
        timers.pop(student_id, None)
        ...
    return jsonify({"ok": True})
```
- `/timer_stop`… コメントにある通り、ユーザーが「停止」して、この後クライアント側の確認画面で保存するか破棄するかを選ぶタイミングで呼ばれる、状態を問わない汎用のクリア処理です。サーバー側にはもう計測中・休憩中の状態として残しておく必要が無いため、単純にエントリを削除します。
