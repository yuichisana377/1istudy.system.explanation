## 1. `Cardmaker-listview.js`（214行）— 一覧で見る画面

プレイモード選択の「一覧で見る」を選ぶと開く、1問ずつめくる学習画面とは違い、**全カードの問題と答えをまとめてスクロールで見られる**画面です。[07_Cardmaker.js_その7_学習モードとクイズ再生.md](07_Cardmaker.js_その7_学習モードとクイズ再生.md)で紹介した`openListView()`の本体がここにあります。

### 1.1 画面を開く（24〜40行）

### 1.3 描画：`renderListView()`（70〜198行）

この関数は、これまでのCardMakerの中でも珍しく、**すべて`document.createElement`によるDOM API組み立て**で作られています（`innerHTML`へのテンプレート文字列の流し込みをほぼ使っていません）。

```js

  const pool = getListViewPool();
  const unsureCount = pool.filter(listViewIsUnsure).length;
  const cards = listViewFilter === 'unsure' ? pool.filter(listViewIsUnsure) : pool;

  document.getElementById('list-view-tab-all').textContent = `すべて (${pool.length})`;
  document.getElementById('list-view-tab-unsure').textContent = `わからないだけ (${unsureCount})`;

  document.getElementById('list-view-tab-unsure').classList.toggle('active', listViewFilter === 'unsure');

  const wrap = document.getElementById('list-view-items');
  wrap.innerHTML = '';

  if (!cards.length) {
    const empty = document.createElement('div');
    empty.className = 'empty-state';
    empty.innerHTML = `<div class="empty-icon">${Icons.cmHtml('emptyList', {size:40})}</div>${listViewFilter === 'unsure' ? 'わからないカードはありません' : 'カードがありません'}`;
    wrap.appendChild(empty);
    return;
  }

  cards.forEach((c, i) => {
    const deckId = c.__deckId || studyDeckId;
    const qText  = listViewReverse ? c.answer   : c.question;
    const qImgs  = listViewReverse ? c.imgs_a   : c.imgs_q;
    const aText  = listViewReverse ? c.question : c.answer;
    const aImgs  = listViewReverse ? c.imgs_q   : c.imgs_a;

    const item = document.createElement('div');
    item.className = 'list-view-item';
    item.dataset.key = cardKey(c); // ★ 検索結果などから、この問題までスクロールするための目印

    const head = document.createElement('div');
    head.className = 'list-view-item-head';

    const num = document.createElement('div');
    num.className = 'list-view-item-num';
    num.textContent = i + 1;
    head.appendChild(num);

      const d = decks.find(x => x.id === deckId);
      if (d) {
        const tag = document.createElement('div');
        tag.className = 'list-view-deck-tag';
        tag.textContent = d.name;
        head.appendChild(tag);
      }
    }

    if (listViewIsUnsure(c)) {
      const badge = document.createElement('span');
      badge.className = 'list-view-unsure-badge';
      badge.innerHTML = Icons.cmHtml('bookmark', {size:13});

    editBtn.innerHTML = Icons.html('edit', {size:14});

    head.appendChild(editBtn);

    item.appendChild(head);

    const qTag = document.createElement('div');
    qTag.className = 'list-view-q-tag';
    qTag.textContent = '問題';
    item.appendChild(qTag);

    const qEl = document.createElement('div');
    qEl.className = 'list-view-q-text';
    item.appendChild(qEl);
    setMathText(qEl, qText);

    if (qImgs && qImgs.length) {

      qImgWrap.className = 'list-view-imgs';
      renderImgList(qImgWrap, qImgs); // ★ Cardmaker.js側の共通ヘルパー（XSS対策：src属性をDOMプロパティで設定）

    const aTag = document.createElement('div');
    aTag.className = 'list-view-a-tag';
    aTag.textContent = '解答';
    item.appendChild(aTag);

    const aEl = document.createElement('div');
    aEl.className = 'list-view-a-text';
    item.appendChild(aEl);
    setMathText(aEl, aText);

    if (aImgs && aImgs.length) {
      const aImgWrap = document.createElement('div');
      aImgWrap.className = 'list-view-imgs';
      renderImgList(aImgWrap, aImgs); // ★ Cardmaker.js側の共通ヘルパー（XSS対策：src属性をDOMプロパティで設定）

    if (c.explanation) {

      eEl.className = 'list-view-e-text';
```

- 番号・（フォルダ表示なら）元のデッキ名タグ・「わからない」バッジ・編集ボタン・問題文・問題の画像・解答・解答の画像・（あれば）解説、という多くの部品を、1つずつ`createElement`で作って`appendChild`で積み上げています。徹底してDOM APIで組み立てているのは、この画面が扱うデータ（問題文・解答・画像）がすべて「他の人が作ったカードかもしれない」ユーザー入力だからだと考えられます（[08_Cardmaker.js_その8_画像処理と基盤機能.md](08_Cardmaker.js_その8_画像処理と基盤機能.md)の`renderImgList`と同じ安全性の考え方）。

### 1.3.1 ★ 2026/09/05 追記：この一覧の中だけを絞り込む検索欄

- 単語検索とは違い、`decks`から既に読み込み済みの`cards`をその場でフィルタするだけなのでサーバー通信が発生しない。そのためデバウンス（`onSearchInput`の150ms待ち）は不要で、入力のたびに即座に`renderListView()`し直している。
- タブ（すべて/わからないだけ）による絞り込みの**後**にキーワード絞り込みを重ねる（`filteredByTab.filter(listViewMatchesSearch)`）ので、タブの件数バッジ（`すべて (N)`）自体は検索キーワードに関係なくタブ本来の件数を示し続ける。
- 一致範囲は問題文・解答に加えて解説（`c.explanation`）も対象にした（単語検索は問題文・解答のみ）。一覧画面は元々解説も表示しているため、探したい語が解説側にしかない場合にも対応できるようにした判断。
- `openListView()`と、単語検索から直接ジャンプする`openSearchResult()`（`openListView()`を経由しない別経路）の両方で、`listViewSearchQuery`と入力欄の値を毎回リセットしている。リセットし忘れると、前回開いたときの検索語が残ったまま新しい一覧が描画され、目的のカードが（一致しないという理由で）表示されない事故になるため。

## まとめ

以上で、`Cardmaker.html`本体・`Cardmaker.js`（9パート）・5つの遅延読み込みチャンクすべての解説が完了しました。CardMaker全体を通じて繰り返し出てきた設計上の考え方を、最後に振り返っておきます。

- **キャッシュを先に見せて、あとから本物のデータで置き換える**（`localStorage`優先表示 → サーバーから最新化）。
- **非同期処理のあとは、待っている間に状態が変わっているかもしれないので、古い参照を信用せず必ず最新の状態から探し直す**（`decks = loadDecks()`のやり直しパターン）。
- **サーバーへの同期は裏で順番待ちの列に並べ、強制的な再取得の直前だけそれを待つ**（`queueSyncDeckToServer`/`waitForPendingSync`）。
- **ユーザー入力を扱う描画は`esc()`か`document.createElement`で安全に組み立て、固定文字列（アイコン等）だけは`innerHTML`を使う**、という一貫した使い分け。
- **重い機能は最初から読み込まず、必要になってから／裏で少しずつ読み込む**（遅延読み込みチャンク）。
- **1回の失敗で行き止まりにせず、常にユーザーが選べる回復手段（再試行・空のまま続行・ローカルのみ保存など）を用意する**。

これで`bot.1istudy.web/Cardmaker.html`＋`Cardmaker.js`＋補助5ファイルの解説はすべて完了です。続きは[../03_Timetable/00_HTML構造とページ全体像.md](../03_Timetable/00_HTML構造とページ全体像.md)で、時間割ページ（`Timetable.html`/`Timetable.js`）の全体像から解説します。
