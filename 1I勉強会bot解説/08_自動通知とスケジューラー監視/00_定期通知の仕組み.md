# 自動通知とタイマー監視ループ（`bot.py` 2025〜2203行）

対象：`bot.py`の「自動通知」「勉強タイマーの定期チェック」セクション。ここで定義されている関数（`send_tomorrow_plans`など）は、この時点ではまだ「いつ実行するか」は決まっていません。実際にスケジュール（毎朝5:30に実行、など）に登録する処理は、ファイルの末尾にある「スケジューラー & 起動」の章でまとめて行われます。

## 1. 共通の下ごしらえ（2025〜2038行）

```python
def strip_note(content: str) -> str:
    if not content:
        return content
    return content.split(NOTE_SEP)[0]
```
- `NOTE_SEP = "\n📝備考："`（このすぐ上で定義）… フロント側（`Plan.js`）は、予定に「備考」欄が入力された場合、本文の末尾にこの決まった区切り文字列を付けて備考を埋め込みます。
- `strip_note`は、Discordへの自動通知メッセージには**備考を含めず、予定本文だけを送る**ために、この区切り文字列より前の部分だけを取り出します。`.split(NOTE_SEP)[0]`… 区切り文字列で分割した結果の最初の要素（＝区切り文字列より前の部分）を取ります。

```python
def is_holiday(guild_id: int, date_str: str) -> bool:
    tt = load_timetable(guild_id)
    ov = tt.get(f"holiday:{date_str}")
    return bool(ov) and ov.get("type") == "holiday"
```
- 指定した日付が「休校」に設定されているかどうかを調べます。`load_timetable`（時間割データ。次の章で解説）から`f"holiday:{date_str}"`というキーのオーバーライド情報を取得し、それが存在し、かつ種類が`"holiday"`であれば休校と判定します。

## 2. 前日夜の通知：`send_tomorrow_plans`（2041〜2069行）

```python
async def send_tomorrow_plans():
    now = datetime.now(JST)
    quiet_if_empty = now.weekday() in (4, 5)  # 4=金, 5=土
    for filename in list_all_configs():
        guild_id = int(filename.replace("config_", "").replace(".json", ""))
        config = load_config(guild_id)
        tomorrow = (now + timedelta(days=1)).strftime("%Y-%m-%d")
        plans = [p for p in load_plans(guild_id) if p["date"] == tomorrow]
        if plans:
            msg = "こんばんは！明日の予定です。\n"
            for p in plans:
                msg += f"・{p['subject']} {strip_note(p['content'])}\n"
        else:
            if quiet_if_empty or is_holiday(guild_id, tomorrow):
                continue
            msg = "こんばんは！明日の予定はありません。\n"

        for config_key in TOMORROW_NOTIFY_CHANNEL_KEYS:
            channel_id = config.get(config_key)
            if not channel_id:
                continue
            channel = bot.get_channel(channel_id)
            if not channel:
                continue
            await channel.send(msg + "@everyone")
```
- `for filename in list_all_configs():`… [../02_データ保存基盤/02_設定ファイルと不正文字チェック.md](../02_データ保存基盤/02_設定ファイルと不正文字チェック.md)で見た`list_all_configs`で、今まで一度でも設定されたことがある**全てのDiscordサーバー**を1つずつ処理します。1つのBotプロセスが、複数のDiscordサーバーの通知を同時にまとめて処理できるようになっています。
- `now.weekday()`… Pythonの`weekday()`は月曜を`0`として、日曜が`6`になる番号を返します。`4`は金曜、`5`は土曜です。
- `quiet_if_empty = now.weekday() in (4, 5)`… ここが少し分かりにくいポイントです。この関数は「前日夜」に実行される通知なので、実行日が金曜なら「明日＝土曜」、実行日が土曜なら「明日＝日曜」の通知になります。土日は元々授業が無く予定が入らないことが多いため、コメントにある通り「予定が無ければ通知自体を送らない（静かにする）」よう、`quiet_if_empty`というフラグを立てておきます。
- 実際に明日の予定を`plans`（リスト内包表記で日付が一致するものだけ抽出）に集め、予定があればそれを列挙したメッセージを、無ければ「予定はありません」という空メッセージを組み立てます。ただし空の場合、`quiet_if_empty`が真、または`is_holiday`で休校と判定された場合は、`continue`でこのguildの処理をスキップし、通知自体を送りません（土日や休校日に「予定はありません」という当たり前の通知が毎回届いて煩わしくならないようにする配慮です）。
- `TOMORROW_NOTIFY_CHANNEL_KEYS = ("remind_channel_id", "remind_channel_id_dorm")`（このすぐ上で定義）… 通生用・寮生用の**両方**のチャンネルキーが列挙されており、`for config_key in TOMORROW_NOTIFY_CHANNEL_KEYS:`でそれぞれについて、設定されていれば（`config.get(config_key)`が存在すれば）同じメッセージを送信します。前日夜の通知は、通生・寮生どちらも同じ「明日の予定」で構わないため、両方に同じ内容を送る設計です。
- `bot.get_channel(channel_id)`… 保存されているチャンネルIDから、実際のDiscordチャンネルオブジェクトを取得します。もし該当するチャンネルが見つからなければ（Bot がそのチャンネルから外された、チャンネル自体が削除された等）`continue`でスキップします。
- `await channel.send(msg + "@everyone")`… メッセージの末尾に`@everyone`（そのチャンネルの全員にメンション通知を送るDiscordの特殊な記法）を付けて送信します。

## 3. 当日朝の通知：`send_today_plans_for`（2071〜2108行）

```python
async def send_today_plans_for(config_key: str):
    now = datetime.now(JST)
    quiet_if_empty = now.weekday() in (5, 6)  # 5=土, 6=日
    for filename in list_all_configs():
        guild_id = int(filename.replace("config_", "").replace(".json", ""))
        config = load_config(guild_id)
        channel_id = config.get(config_key)
        if not channel_id:
            continue
        channel = bot.get_channel(channel_id)
        if not channel:
            continue
        today = now.strftime("%Y-%m-%d")
        plans = [p for p in load_plans(guild_id) if p["date"] == today]
        if plans:
            msg = "おはようございます！今日の予定です。\n"
            for p in plans:
                msg += f"・{p['subject']} {strip_note(p['content'])}\n"
        else:
            if quiet_if_empty or is_holiday(guild_id, today):
                continue
            msg = "おはようございます！今日の予定はありません。\n"
        await channel.send(msg + "@everyone")

async def send_today_plans_commute():
    """通生向け：朝5:30の通知（既存のremind_channel_idを使用）"""
    await send_today_plans_for("remind_channel_id")

async def send_today_plans_dorm():
    """寮生向け：朝7:20の通知（remind_channel_id_dormを使用）"""
    await send_today_plans_for("remind_channel_id_dorm")
```
- 考え方は`send_tomorrow_plans`とほぼ同じですが、こちらは`config_key`を**引数として受け取る**設計になっています。これは、通生（朝5:30）と寮生（朝7:20）では**通知する時刻そのものが違う**ため、前日夜のように「1回の実行で両方のチャンネルに同時送信」ができず、別々の時刻に別々に呼び出す必要があるからです。
- `send_today_plans_commute`/`send_today_plans_dorm`… `send_today_plans_for`に、それぞれ通生用・寮生用のチャンネルキーを固定で渡すだけの、薄いラッパー関数です。この2つの関数が、実際にスケジューラーへ登録される名前になります（後の章で確認します）。
- `quiet_if_empty`の曜日判定が`(5, 6)`（土・日）になっている点に注目してください。こちらは「当日朝」の通知なので、実行日そのものが土曜か日曜であれば静かにする、という単純な判定です（`send_tomorrow_plans`の「翌日が土日になる、実行日は金・土」という1日ズレた判定とは異なります）。

## 4. 週間まとめ通知：`send_weekly_plans`（2110〜2150行）

```python
WEEKLY_NOTIFY_CHANNEL_KEYS = ("remind_channel_id", "remind_channel_id_dorm")
WEEKDAY_JP = ["月", "火", "水", "木", "金", "土", "日"]

async def send_weekly_plans():
    now = datetime.now(JST)
    week_start = (now + timedelta(days=1)).date()   # 翌日の月曜
    week_end = week_start + timedelta(days=6)        # その週の日曜

    for filename in list_all_configs():
        guild_id = int(filename.replace("config_", "").replace(".json", ""))
        config = load_config(guild_id)
        plans = [
            p for p in load_plans(guild_id)
            if week_start <= datetime.strptime(p["date"], "%Y-%m-%d").date() <= week_end
        ]

        if plans:
            plans_by_date = {}
            for p in plans:
                plans_by_date.setdefault(p["date"], []).append(p)

            msg = f"📅 今週（{week_start.strftime('%m/%d')}〜{week_end.strftime('%m/%d')}）の予定です！\n"
            for date_str in sorted(plans_by_date.keys()):
                d = datetime.strptime(date_str, "%Y-%m-%d").date()
                msg += f"\n**{d.strftime('%m/%d')}（{WEEKDAY_JP[d.weekday()]}）**\n"
                for p in plans_by_date[date_str]:
                    msg += f"・{p['subject']} {strip_note(p['content'])}\n"
        else:
            msg = f"📅 今週（{week_start.strftime('%m/%d')}〜{week_end.strftime('%m/%d')}）の予定はありません。\n"

        for config_key in WEEKLY_NOTIFY_CHANNEL_KEYS:
            ...
            await channel.send(msg + "\n@everyone")
```
- コメントにある通り、これは毎週日曜14:00に、翌日（月曜）から日曜までの1週間分の予定をまとめて通知する処理です。
- `week_start = (now + timedelta(days=1)).date()`… 実行日（日曜）の翌日、つまり月曜の日付を計算します。`week_end = week_start + timedelta(days=6)`で、その6日後（＝次の日曜）までを範囲とします。
- `plans_by_date = {}` からの`for`ループと`plans_by_date.setdefault(p["date"], []).append(p)`… 対象期間の予定を、日付ごとにグループ分けする定番の書き方です。`setdefault(キー, [])`は「そのキーが辞書に無ければ空リストを新規作成してから、それを返す」という意味で、これにより「1日に複数の予定がある場合はリストにまとめて追加していく」という処理を、事前にキーの存在チェックをせずに簡潔に書けます。
- `sorted(plans_by_date.keys())`… 日付文字列（`YYYY-MM-DD`形式）は、そのまま文字列として並び替えても日付順になる、という性質を利用しています（`"2026-08-05"`より`"2026-08-20"`の方が文字列としても大きいため）。
- `WEEKDAY_JP[d.weekday()]`… `weekday()`が返す0〜6の番号を使って、`WEEKDAY_JP`リストから日本語の曜日名を引きます（リストのインデックスとして番号をそのまま使う、シンプルな対応表の実装です）。
- こちらも通生・寮生の両方のチャンネルに同じ内容を送ります（`WEEKLY_NOTIFY_CHANNEL_KEYS`）。

## 5. 勉強タイマーの定期監視：`check_study_timers`（2152〜2202行）

コメントにある通り、これは[../04_勉強タイマー/00_勉強タイマーの状態管理.md](../04_勉強タイマー/00_勉強タイマーの状態管理.md)で見た「3時間経過による自動休憩」の判定を、**クライアントのタブが開いているかどうかに関係なく**、サーバー側で一定間隔ごとに全guild分チェックするための定期ジョブです。各APIエンドポイント（`timer_state`など）へのアクセス時にも同じ判定（`_sync_timer_entry`経由）が行われているため、この定期ジョブは「誰もアプリを開かなかった場合」の保険として働きます。コメントの通り、`_finalize_study_timer`は**冪等**（べきとう。同じ入力に対して何度呼んでも同じ結果になり、副作用が積み重ならない性質）なので、両方から二重に判定されても問題は起きません。

```python
async def check_study_timers():
    now_ms = int(time.time() * 1000)
    for filename in list_all_configs():
        try:
            guild_id = int(filename.replace("config_", "").replace(".json", ""))
        except ValueError:
            continue

        try:
            timers = await async_load_study_timers(guild_id)
        except Exception as e:
            print(f"[WARN] study_timers 読み込みに失敗しました（guild_id={guild_id}）: {e}")
            continue
        if not timers:
            continue

        new_timers = dict(timers)
        notifications = []
        changed = False
        for student_id, entry in timers.items():
            new_entry, notify_kind = _finalize_study_timer(entry, now_ms)
            if new_entry != entry:
                changed = True
                if new_entry is None:
                    new_timers.pop(student_id, None)
                else:
                    new_timers[student_id] = new_entry
            if notify_kind:
                notifications.append((student_id, notify_kind))

        if not changed:
            continue

        try:
            await async_save_study_timers(guild_id, new_timers)
        except DataWriteError as e:
            print(f"[WARN] study_timers 保存に失敗しました（guild_id={guild_id}）。次回のチェックで再試行します: {e}")
            continue

        for student_id, kind in notifications:
            _try_notify_timer(guild_id, student_id, MSG_TIMER_AUTO_PAUSED)
```
- 全guildを回り、各guildの`study_timers`（今まさに計測中の全生徒分のエントリ）を1件ずつ`_finalize_study_timer`で評価します。これは[../04_勉強タイマー/00_勉強タイマーの状態管理.md](../04_勉強タイマー/00_勉強タイマーの状態管理.md)で見た`_sync_timer_entry`と似ていますが、あちらが「1人分」を扱うのに対し、こちらは「1つのguildの全生徒分」をまとめて処理する点が違います。
- `changed`フラグ… 誰か1人でも状態が変わった場合だけ`True`になります。**誰も3時間を超えていなければ、そのguildについては保存処理自体をスキップします**（`if not changed: continue`）。無駄な書き込み・SSE通知を避けるための最適化です。
- `notifications`… 「誰に、どんな通知を送るべきか」をいったんリストに溜めておき、**保存が成功した後で**まとめて送信します。これは[../04_勉強タイマー/00_勉強タイマーの状態管理.md](../04_勉強タイマー/00_勉強タイマーの状態管理.md)の`_sync_timer_entry`と同じ設計思想で、保存に失敗した場合（`DataWriteError`）は通知を送らず、`print`で警告を出すだけにしています。コメントにある通り「次回のチェックで再試行します」という前提のため、慌てて例外を握りつぶさずに次のループへ委ねる形です。
- `try: guild_id = int(...) except ValueError: continue`… `list_all_configs()`が返すファイル名から`guild_id`を取り出す際、万一想定外の形式のファイル名が紛れ込んでいても、そのファイルだけをスキップして処理全体は止めない、という安全策です。
