# CardMaker「4択にする」の事前生成キャッシュ（`bot.py`）（2026/08/26追加）

対象：`bot.py`の`_cardmaker_generate_choice_cache`・`GET /cardmaker_choice_cache`・
`save_cards`／`_delete_card_deck_file`への追記部分。

## 課題：学習を始めるたびにAIの計算が使い捨てになっていた

[03_AI誤答強化API.md](03_AI誤答強化API.md)で解説した`/cardmaker_ai_distractors`は、
生徒が実際に学習を始めた瞬間にその場でAIへ問い合わせる設計だった。これには
構造的な無駄があった：**同じデッキを複数の生徒が学習しても、それぞれが独立に
同じような誤答強化をAIへ依頼し、結果はその生徒の学習セッションが終われば
捨てられる**。11人規模とはいえ、人気のデッキを何人もが学習すれば、その回数分
だけ同じ計算が繰り返されることになる。

そこで、デッキを「公開」保存したタイミングで**先に**選択肢一式を作っておき、
`four_choice_cache_<filename>.json`というファイルに保存しておくことにした。
学習する生徒は、間に合っていればこのキャッシュを読むだけで済み、AIの応答を
待つ必要が無くなる。

## 生成のトリガー：`save_cards`の「公開」保存時だけ

```python
if not card_payload["choice_mode"] and not is_quiz_archive and not incomplete:
    Thread(target=_cardmaker_generate_choice_cache, args=(guild_id, filename, cards), daemon=True).start()
```

- **`incomplete`（下書き中フラグ）がFalseのときだけ発火**：`save_cards`は
  CardMakerの「作成中」デッキの自動保存でも頻繁に呼ばれる（下書き編集の
  たびに呼ばれることがある）。ここで毎回AIへ問い合わせてしまうと、
  下書きを触るたびに無駄な計算が走ってしまう。「公開」した瞬間、および
  公開済みデッキを編集保存した瞬間（どちらも`incomplete=False`）だけに
  絞ることで、実際に生徒の目に触れるタイミングに限定している。
- **選択式デッキ（`choice_mode`）・クイズ過去問（`is_quiz_archive`）は対象外**：
  前者は既に選択肢を持っている（[../../1I勉強会web解説/02_Cardmaker/06_Cardmaker.js_その6](../../1I勉強会web解説/02_Cardmaker/06_Cardmaker.js_その6_カード編集と学習データ同期.md)参照）、
  後者は問題の中身を編集できない仕様のため。
- `Thread(..., daemon=True).start()`で`save_cards`のレスポンス自体はブロックしない
  （みんなでクイズのAI強化と同じ設計方針）。

## `_cardmaker_generate_choice_cache`：2段階で書き込む

```python
def _cardmaker_generate_choice_cache(guild_id, deck_filename, cards):
    try:
        fallback = _build_cardmaker_fallback_choices(cards)
        _cardmaker_cache_write(deck_filename, fallback)
        if not fallback or not OLLAMA_HOST:
            return
        ...（記述系優先・最初の1問だけバッチ1・以降3問ずつでAI強化）...
        current, sha = local_get(cache_filename)
        ...
        local_put(cache_filename, current, sha)
    except Exception as ex:
        print(f"[WARN] ...: {ex}")
```

1. **まず`_build_cardmaker_fallback_choices`（綴り類似度ベース、`_pick_distractors`を
   再利用）で全カード分を即座に計算し、ファイルに書く**。この時点でAIの応答を
   一切待たないため、公開してから数秒以内には「即席の4択」が使える状態になる。
2. `OLLAMA_HOST`が設定されている場合だけ、続けてAIへの問い合わせに入る。
   [02_Cardmaker/07_Cardmaker.js_その7](../../1I勉強会web解説/02_Cardmaker/07_Cardmaker.js_その7_学習モードとクイズ再生.md)の
   フロント側ロジック（`scheduleFourChoiceAiEnhancement`）とほぼ同じ考え方
   （記述系カードを先に、最初の1問だけバッチサイズ1、以降3問ずつ）を、
   今度はサーバー側で実行する。1バッチ処理するたびにファイルを都度上書き
   （`local_put`）するので、生成の途中でエラーが起きても、そこまでにAIが
   改善した分は失われない。
3. 例外は丸ごと握りつぶし、ログに警告を出すだけ（クイズ側と同じベスト
   エフォート方針）。既にステップ1で即席4択は書き込み済みなので、AI強化が
   失敗してもキャッシュ自体が空になることはない。

`_build_cardmaker_fallback_choices`は、答えの異なりが`FOUR_CHOICE_POOL_MIN_SIZE`
（10）を超えないカード・idが無いカード・答えが空のカードを除外する。この基準は
[02_Cardmaker/07_Cardmaker.js_その7](../../1I勉強会web解説/02_Cardmaker/07_Cardmaker.js_その7_学習モードとクイズ再生.md)の
`FOUR_CHOICE_POOL_MIN_SIZE`（クライアント側）と完全に一致させてある。

## `GET /cardmaker_choice_cache`：取得と「ローテーション」

```python
@app.route("/cardmaker_choice_cache", methods=["GET"])
def cardmaker_choice_cache():
    guild_id, _student_id, err = require_member_session_get()
    if err:
        return err
    ...
    data, sha = local_get(cache_filename)
    if not isinstance(data, dict) or not isinstance(data.get("cards"), dict):
        return jsonify({"ok": True, "cards": {}})

    if not data.get("used"):
        data["used"] = True
        local_put(cache_filename, data, sha)
        _cardmaker_trigger_cache_regen(guild_id, filename)

    return jsonify({"ok": True, "cards": data["cards"]})
```

- **ログイン必須**（`require_member_session_get`）：`/cardmaker_ai_distractors`と
  同じ理由で、このAPIもバックグラウンドAI再生成をトリガーしうるため。
- **キャッシュが無い/壊れていれば`cards: {}`を返すだけ**（エラーにはしない）。
  呼び出し元（Cardmaker.js）は、対象カードが無ければローカルの即席4択＋
  ローカルAI強化にそのままフォールバックする設計なので、これで十分。
- **「誰か1人でも1回触ったらリセット」のローテーション方式**：キャッシュの
  `used`フラグがまだFalse（＝生成されてからまだ誰も取りに来ていない）なら、
  この呼び出しでTrueに変え、`_cardmaker_trigger_cache_regen`で**裏で新しい
  4択をもう一度作り直す**（生成し直し）。複雑な無効化判定（カードのどこが
  変わったら再生成すべきか、を都度判定するロジック）を実装せず、
  「誰かが実際に使ったら、次の人のために裏でまた作り直しておく」という
  単純なローテーションにすることで、キャッシュを常に「そこそこ新しい」
  状態に保っている。2人目以降の生徒は、`used`が既にTrueなので単に
  現在のキャッシュ内容を受け取るだけ（追加の再生成はトリガーしない）。
- `_cardmaker_trigger_cache_regen`は`_CARDMAKER_CACHE_REGEN_INFLIGHT`（`set`＋`Lock`）
  で、同じデッキに対する再生成が同時に2つ走らないようにガードしている
  （複数の生徒がほぼ同時に「初めての利用」をした場合の二重生成防止）。
  再生成時は`get_card_file_for_guild`でデッキの**最新の**カード内容を読み直して
  から`_cardmaker_generate_choice_cache`を呼ぶ（＝再生成のたびに、もし直前に
  デッキが編集されていればその内容が反映される）。

## デッキ削除時の後始末

`_delete_card_deck_file`（デッキ本体削除の共通処理）に、対応する
`four_choice_cache_<filename>.json`の削除も追加した。無くても実害は無いが
（存在しないデッキのキャッシュファイルが参照されることはない）、削除済み
デッキ分のファイルが溜まり続けるのを防ぐための後始末。

## フロント側との対応

キャッシュの消費・検証・「サーバー版が無ければローカル生成にフォールバック」
という判断はすべてフロント側（`Cardmaker.js`の`applyServerChoiceCaches`）が
担う。詳細は
[../../1I勉強会web解説/02_Cardmaker/07_Cardmaker.js_その7_学習モードとクイズ再生.md](../../1I勉強会web解説/02_Cardmaker/07_Cardmaker.js_その7_学習モードとクイズ再生.md)

## 実機での動作確認

コンテナ内で`_build_cardmaker_fallback_choices`・`_cardmaker_generate_choice_cache`
を実際に12枚（元素記号）のテストデッキで実行し、以下を確認済み：
- 即席4択が12枚全カードぶん即座に計算される。
- AI強化込みの全体生成は約74秒（1問目バッチ1、以降3問ずつ、短い単語同士のため
  比較的速い）。
- 生成後のキャッシュファイルには12枚分すべてAI強化済みの誤答が入っており、
  例えば「水素(H)」の誤答が綴り類似度ベースの`["C","F","O"]`から、AIによって
  意味的に近い`["He","O","N"]`（Heは特に紛らわしい）へ差し替わっていた。
