# 共有リンク：CardMakerのUIと、ログイン不要の閲覧・承認ページ

サーバー側の実装は[../../1I勉強会bot解説/22_FlaskAPI_デッキ共有リンク/00_共有リンクの発行と取り消し.md](../../1I勉強会bot解説/22_FlaskAPI_デッキ共有リンク/00_共有リンクの発行と取り消し.md)を参照。この章ではWeb側（`bot.1istudy.web`）を、①`Cardmaker.html`/`Cardmaker.js`への追加分、②ログイン不要の新規ページ2つ（`DeckShare.html`＝閲覧ビューア、`ShareApproval.html`＝作成者の承認ページ）、③`PendingShareCheck.js`（Discord未連携時の受け皿）の順に見ていきます。

## 1. CardMaker側：デッキメニューへの追加（`Cardmaker.html` 639〜700行、`Cardmaker.js` 1871〜2068行）

デッキ一覧の✏️メニュー（`modal-deck-menu`。[02_Cardmaker/02_Cardmaker.js_その2_一覧画面とフォルダ操作.md](../02_Cardmaker/02_Cardmaker.js_その2_一覧画面とフォルダ操作.md)参照）に、「フォルダに移動する」と「非公開に戻す」の間へ新しい項目を追加してあります。

```html
<div class="menu-item" id="menu-share-item" onclick="menuShare()" style="display:none">
  ...共有リンクを作る
</div>
```
- `menu-unpublish-item`（非公開に戻す）と同じく、`display:none`が初期値で、`openDeckMenu()`側で公開済みデッキ（`deck.filename`がある）のときだけ表示されます。共有リンクはサーバー上の実ファイルが対象なので、非公開（ローカルのみ）のデッキには出しようがないためです。

`Cardmaker.js`側の`menuShare()`は、`modal-deck-share`（共有リンクの管理モーダル）を開き、`/list_deck_shares`でこのデッキの共有中リンク一覧と本日の残り件数を取得して表示します。

```javascript
async function createDeckShareLink() {
  ...
  const res = await fetch(`${API_BASE}create_deck_share`, {
    method: 'POST', headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ guild_id: GUILD_ID, session_token: session?.session_token, filename: deckShareCtx.filename }),
    ...
  });
  const data = await res.json();
  ...
  if (!data.ok) {
    if (data.error === 'creator_approval_required') {
      const deck = decks.find(d => d.filename === deckShareCtx.filename);
      closeModal('modal-deck-share');
      openRequestShareModal(deckShareCtx.filename, deck ? deck.name : deckShareCtx.filename, data.owner_nickname);
      return;
    }
    if (data.error === 'share_limit_reached') {
      errEl.textContent = '本日の共有作成上限（3件）に達しています。明日また作成できます。';
      ...
    }
    ...
  }
  await loadDeckShareList();
  showBanner('共有リンクを作成しました', ...);
  copyShareLink(data.url);
}
```
- `menuDelete()`/`menuUnpublish()`が`creator_approval_required`を受け取ったときに`openRequestDeleteModal()`（削除の確認依頼フォーム）を開くのと全く同じパターンで、`create_deck_share`が`creator_approval_required`を返したら`openRequestShareModal()`（共有の確認依頼フォーム、`modal-request-share`）を開きます。中身は`/request_deck_share`を叩くだけの、`submitRequestDelete()`と対になる`submitRequestShare()`です。
- `share_limit_reached`（1日3件の上限）は削除フローには無い、この機能特有のエラーコードです。
- 発行に成功したら、一覧を再取得して画面に反映しつつ、`copyShareLink()`でURLをクリップボードにも自動コピーします（[08_画像処理と基盤機能.md](../02_Cardmaker/08_Cardmaker.js_その8_画像処理と基盤機能.md)で見た`navigator.clipboard`と同じAPI）。

管理モーダル内の各リンクには「取り消す」ボタンがあり、`revokeDeckShare(token)`が`/revoke_deck_share`を叩きます。確認ダイアログには、削除・非公開系の操作と同じ`showCmConfirm`（[01_Cardmaker.js_その1_ログインとデータ管理.md](../02_Cardmaker/01_Cardmaker.js_その1_ログインとデータ管理.md)参照）を使っています。

## 2. `PendingShareCheck.js`：Discord未連携時の受け皿

`PendingDeleteCheck.js`（[10_DeleteApproval](../10_DeleteApproval/00_DeleteApproval解説.md)参照）と全く同じ構造の、独立したIIFE（即時実行関数）です。`index.html`/`Timetable.html`/`Cardmaker.html`/`Notice.html`/`StudyLog.html`/`TanCheck.html`/`ServiceInfo.html`の`<script>`末尾（`PendingDeleteCheck.js`の直後）に読み込みタグが追加されています。

- ページを開くたびに`/pending_share_requests`を叩き、自分（デッキ作成者）宛の未確認の共有依頼があれば、DOM APIで組み立てたモーダル（承諾/拒否/あとで、の3択）を表示します。
- `PendingDeleteCheck.js`と同じグローバル名の再宣言を避ける方針（`API_BASE`等をconstで再宣言せず、値をリテラルのまま使う）も踏襲しています。
- 承諾/拒否は`/respond_deck_share_request`を叩くだけです（削除確認と違い、承諾してもこの場でリンクは発行されません。[../../1I勉強会bot解説/22_FlaskAPI_デッキ共有リンク/01_閲覧APIと依頼承認フロー.md](../../1I勉強会bot解説/22_FlaskAPI_デッキ共有リンク/01_閲覧APIと依頼承認フロー.md)参照）。

## 3. `ShareApproval.html`/`.js`：作成者向けの承認ページ

`DeleteApproval.html`/`.js`（[10_DeleteApproval](../10_DeleteApproval/00_DeleteApproval解説.md)）をほぼそのまま踏襲した、ログイン不要のページです。DMのリンク（`?token=...`）を開くと：
1. `/share_request_info`でトークンを検証し、「誰が・どのデッキを・なぜ共有したいか」を表示。
2. 「承諾する」/「拒否する」ボタンが`/respond_deck_share_request`を叩く。
3. 結果メッセージ（`sa-result`）を表示して終わり。

`DeleteApproval.js`との違いは、承認後の案内文だけです（「削除しました」ではなく「承諾しました。依頼者が共有リンクを発行できるようになりました」のような、レスポンスの`message`フィールドをそのまま表示する作り）。表示内容（依頼理由・デッキ名等）はすべて利用者入力のテキストなので、`DeleteApproval.js`と同じ理由で`textContent`だけで組み立てています。

## 4. `DeckShare.html`/`.js`：ログイン不要の閲覧ビューア

このページが、実際に共有リンクを受け取った人（ログインしていなくてよい）が開く画面です。設計上の最重要点は、**このデッキ以外の情報を一切表示・取得しない**ことです。

- ドロワー（サイドメニュー）を持たず、`Login.html`のようなアカウント関連の要素も一切ありません。読み込むJSは`Icons.js`と`DeckShare.js`だけです（`Cardmaker.js`本体は読み込みません。ログイン前提の巨大なファイルであり、このページでは不要な機能ばかりだからです）。
- 画面のCSSは`Cardmaker.css`をそのまま流用しています。`.screen`・`.topbar`・`.study-top`/`.study-bottom`・`.qp-choices`など、[02_Cardmaker/00_HTML構造とページ全体像.md](../02_Cardmaker/00_HTML構造とページ全体像.md)や[07_Cardmaker.js_その7_学習モードとクイズ再生.md](../02_Cardmaker/07_Cardmaker.js_その7_学習モードとクイズ再生.md)で見た暗記カード学習・選択式クイズの画面と**同じクラス・同じ構造**を、ログイン前提のSPA機構（画面切り替え等）無しで直接組み立てています。専用の`DeckShare.css`はスピナーやエラー表示など、ごく小さな追加分のみです。
- `DeckShare.js`は`setMathText`/`simpleMathToLatex`/`findMatchingParen`/`renderImgList`など、数式描画・画像描画のロジックを`Cardmaker.js`から**そのまま複製**しています（[09_Cardmaker.js_その9_数式入力とリアルタイム更新.md](../02_Cardmaker/09_Cardmaker.js_その9_数式入力とリアルタイム更新.md)参照）。`Cardmaker.js`自体を読み込まない設計上、必要な部分だけをこのページ専用に持たせる形です。画像は`renderImgList()`同様、`<img src="${s}">`のようなテンプレート文字列を使わず必ずDOMの`src`プロパティへ代入します（共有デッキ経由で他人が仕込んだ文字列がXSSにならないようにするため）。
- `/deck_share_info?token=...`を取得したあと、`choice_mode`かつ選択式で遊べるカード（`choices`が2つ以上あるもの）が1問でもあれば選択式クイズモード、そうでなければ暗記カード（フリップ学習）モードで表示します。この判定は[07_Cardmaker.js_その7_学習モードとクイズ再生.md](../02_Cardmaker/07_Cardmaker.js_その7_学習モードとクイズ再生.md)の`startSoloQuiz()`と同じ考え方です。
- 「わからない」マーク・自動採点・学習進捗の端末間同期・成績のサーバー送信（ランキング）など、ログイン前提かつ変更を伴う機能は**すべて省いてあります**。選択式クイズの正解数はこの画面の中だけで完結するローカルな表示で、どこにも送信されません。
