# `/quiz_create` とクイズ過去問ランキング（`bot.py` 5129〜5321行）

対象：`bot.py`の`/quiz_create`、および「クイズ過去問（CardMaker内の一人用4択モード）のランキング」セクション。

## 1. `/quiz_create`：ルームの作成（5129〜5216行）

```python
@app.route("/quiz_create", methods=["POST"])
def quiz_create():
    data, guild_id, student_id, nickname, err = _quiz_auth_from_json()
    if err:
        return err

    title = str(data.get("title") or "").strip()[:40] or "みんなでクイズ"

    source = data.get("source")
    if source == "deck":
        deck_filenames = data.get("deck_filenames")
        if not deck_filenames:
            single = data.get("deck_filename")
            deck_filenames = [single] if single else None
        if not deck_filenames:
            return jsonify({"ok": False, "error": "deck_not_found"})
        questions, q_err = _build_deck_questions(deck_filenames, data.get("num_questions"))
        if q_err:
            return jsonify({"ok": False, "error": q_err})
        err = reject_if_bug_chars({"タイトル": title})
        if err:
            return err
    elif source == "manual":
        result, q_err = _validate_manual_questions(data.get("questions"))
        if q_err:
            return jsonify({"ok": False, "error": q_err})
        questions, check_fields = result
        check_fields["タイトル"] = title
        err = reject_if_bug_chars(check_fields)
        if err:
            return err
    else:
        return jsonify({"ok": False, "error": "invalid_source"})
```
- `title = str(data.get("title") or "").strip()[:40] or "みんなでクイズ"`… タイトルは最大40文字に切り詰め、空なら`"みんなでクイズ"`というデフォルト名になります。
- `source`（クイズの元になる出題方法）が`"deck"`か`"manual"`かで、[01_ルーム状態のJSON化と問題の自動生成.md](01_ルーム状態のJSON化と問題の自動生成.md)で見た`_build_deck_questions`（デッキから自動生成）か`_validate_manual_questions`（ホストの手入力を検証）のどちらかに分岐します。それ以外の値は`"invalid_source"`として拒否します。
- `deck_filenames`の後方互換処理：`if not deck_filenames: single = data.get("deck_filename"); deck_filenames = [single] if single else None`… 複数デッキ選択に対応する前は、単一の`deck_filename`という名前のフィールドしかありませんでした。新しいフィールド（`deck_filenames`）が無ければ、古いフィールド（`deck_filename`）を1要素のリストとして使う、というフォールバックです。フロント側が新しい形式に完全移行していなくても、古い呼び出し方のままでも動き続けます。
- どちらの`source`でも、最終的に`reject_if_bug_chars`で不正文字チェックが行われます。`manual`の場合はタイトルだけでなく、[01_ルーム状態のJSON化と問題の自動生成.md](01_ルーム状態のJSON化と問題の自動生成.md)の`_validate_manual_questions`が作った`check_fields`（各問題・各選択肢のテキスト全部）もまとめてチェックされます。

- `allow_late_join`… 「途中参加を許可するか」をホストが選べます。コメントの通り、デフォルト（不許可）では開始と同時にルーム一覧上で実質参加不可になりますが、許可すれば進行中でもルーム一覧に表示され続け、参加できます。★ 追加：許可して`question`/`reveal`/`ranking`中に参加してきた人は`active_from_q`によって「次の問題から」扱いになります（詳しくは[03_ルーム参加と進行API.md](03_ルーム参加と進行API.md)）。ホストは`quiz_create`の時点で常に`active_from_q: 0`（最初から参加扱い）です。
- `with QUIZ_ROOMS_LOCK:`の中で、`_quiz_gc_locked`（期限切れルームの掃除）を行ってから新しいコードを発行し、ルームの全データを1つの辞書として`QUIZ_ROOMS`に登録します。ロックで保護された1つの塊の中で、掃除・コード発行・登録までを一気に終わらせることで、複数のリクエストが同時に来ても、コードの重複や中途半端な登録が起きないようにしています。

### 1.1 追記（2026/08/27）：ホストの詳細設定「ボーナス問題」

「ホストに詳細設定を作成し、そこからボーナス問題をつくる（ランダム・最後の〇問など）得点が2倍になるようにする」との要望で追加。`allow_late_join`のすぐ下に、同じ考え方で新しいフィールドが増えている。

```python
bonus_mode = data.get("bonus_mode")
bonus_indices = set()
if bonus_mode in ("random", "last"):
    try:
        bonus_count = int(data.get("bonus_count"))
    except (TypeError, ValueError):
        return jsonify({"ok": False, "error": "invalid_bonus_count"})
    if bonus_count < 1:
        return jsonify({"ok": False, "error": "invalid_bonus_count"})
    bonus_count = min(bonus_count, len(questions))
    if bonus_mode == "random":
        bonus_indices = set(random.sample(range(len(questions)), bonus_count))
    else:  # "last"
        bonus_indices = set(range(len(questions) - bonus_count, len(questions)))
elif bonus_mode not in (None, "", "none"):
    return jsonify({"ok": False, "error": "invalid_bonus_mode"})
```
- どの問題をボーナス（得点2倍）にするかは、**この作成時点で一度だけ**サイコロを振って`room["bonus_indices"]`（0-indexedの問題番号の集合）に固定してしまう。「ランダム」を選んでも、進行中に問題ごとに再抽選したりはしない——Web側の案内文「ランダムは作成時に抽選して決まり、途中で入れ替わりません」と一致させるための設計。`"random"`は`random.sample`で単純にN問を無作為抽出、`"last"`は`range(len(questions) - bonus_count, len(questions))`で末尾N問をそのまま範囲指定するだけ。
- `bonus_count = min(bonus_count, len(questions))`… 問題数より多いボーナス数を指定されても、全問がボーナス扱いになるだけで壊れないよう丸めている。
- `room["bonus_indices"]`はメモリ上の`set`のまま持つ（`QUIZ_ROOMS`自体がディスクに永続化されないため、JSONシリアライズ可能である必要が無い）。[01_ルーム状態のJSON化と問題の自動生成.md](01_ルーム状態のJSON化と問題の自動生成.md)・[03_ルーム参加と進行API.md](03_ルーム参加と進行API.md)で、この集合を実際にどう使うか（クライアントへの予告・得点計算）を解説する。
