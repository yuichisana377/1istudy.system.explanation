対象：`bot.py`の「Flask API — みんなでクイズ（オンライン早押し4択）」セクション冒頭。[../../1I勉強会web解説/05_Quiz](../../1I勉強会web解説/05_Quiz/00_HTML構造とその1_起動と参加画面.md)で見たクイズ機能の、サーバー側の実装です。ここから約880行にわたって、`bot.py`最大級のセクションが続きます。

## 設計方針（コメントより）

`Quiz.js`から呼ばれるこのセクションは、これまでのCardMakerや予定管理とは根本的にアプローチが違います。**進行中のゲーム状態をディスクに永続化せず、プロセスのメモリ上（`QUIZ_ROOMS`という辞書）だけで管理します**。理由はコメントの通り、ルームの状態は「今まさに進行中のゲーム」にしか意味を持たない一時的なデータだからです。[../06_Discordアカウント連携/00_連携コードとOAuthステート.md](../06_Discordアカウント連携/00_連携コードとOAuthステート.md)の`LINK_CODES`/`OAUTH_STATES`と同じ考え方です。

- `code`（5桁の招待コード）でルームを引きます。
- `state`は`"lobby"`（開始待ち）→`"countdown"`（開始直後の5秒カウントダウン、最初の問題の前だけ）→`"intro"`（「第N問」を大きく見せる区間、毎問の前）→`"question"`（出題中）→`"reveal"`（正解発表）→`"ranking"`（スコア順の途中経過。`QUIZ_RANKING_INTERVAL`問に1度だけ、次の問題がある場合に挟む）→（次の問題があれば`"intro"`に戻る／最終問題の発表後、および間隔に満たない問題の発表後は`"ranking"`を挟まず直接`"ended"`／`"intro"`）と遷移します。
- **ホストの操作待ちにはせず、すべて自動で進行します**。時間経過や全員の回答状況に応じて、サーバー側が勝手に次の段階へ進めます。この判定は各APIリクエストのたびに`_quiz_autoadvance_locked()`でその場評価する、[../04_勉強タイマー/00_勉強タイマーの状態管理.md](../04_勉強タイマー/00_勉強タイマーの状態管理.md)の`study_timers`の自動休憩判定と同じ「アクセスのたびに評価する」方式です（後述する通り、実際にはこれに加えて専用の監視スレッドも追加されています）。フロントは1秒ごとにポーリングしているので、実際の進行から最大でも1秒程度の遅れで反映されます。
- ホスト（作成者）も1人のプレイヤーとして最初から参加者に含まれ、他の参加者と同じように回答してスコアを競えます。そのため、**正解番号はホストにも「発表(reveal)されるまでは」一切渡しません**（渡すとホストだけ先に答えを知れてしまいます）。
- 得点は正解+10pt。そのうち、その問題で一番早く正解した1人だけさらに+2ptのボーナス（合計12pt）が付きます。**得点が同点の場合の順位（`"ranking"`画面・最終結果）は、それまでに回答にかかった時間の合計（`total_answer_time`。押すのが早いほど小さい値）が短い方を上位とします**。一方、正解発表(reveal)中のミニ順位表だけは例外で、スコア順ではなく「その問題に回答したのが早い順（正誤にかかわらず）」で並べます（Kahoot風の演出。全体順位は`"ranking"`画面・最終結果で見せます）。
- **途中参加**（ホストが作成時に`allow_late_join`を有効にした場合）で`question`/`reveal`/`ranking`中に参加した人は、参加した時点の問題には混ざらず、次の問題から（`active_from_q`）アクティブになります。それまでは出題中でも「見学中」（`quiz_state`の`spectating`）として扱われ、全員回答済み判定にも回答受付にも含まれません（後述の[03_ルーム参加と進行API.md](03_ルーム参加と進行API.md)で詳しく解説します）。
- プロセス再起動でルームは全て消えます（＝進行中のクイズは失われます）が、ゲームの性質上（せいぜい数十分で終わる遊び）これは許容されています。

## 3. 状態の自動進行：`_quiz_autoadvance_locked`（4757〜4812行）

```python
def _quiz_autoadvance_locked(room, now):
    while True:
        if room["state"] == "countdown":
            if now - room["countdown_started_at"] < QUIZ_COUNTDOWN_DURATION_SEC:
                return
            room["state"] = "intro"
            room["intro_started_at"] = now
        elif room["state"] == "intro":
            if now - room["intro_started_at"] < QUIZ_INTRO_DURATION_SEC:
                return
            room["state"] = "question"
            room["question_started_at"] = now
            room["intro_started_at"] = None
        elif room["state"] == "question":
            # ★ 途中参加でまだ「見学中」（active_from_q未到達）の人は、全員回答済み
            #   判定の分母・分子どちらからも除外する。
            active_players = [p for p in room["players"].values() if p.get("active_from_q", 0) <= room["current_q"]]
            total = len(active_players)
            answered = sum(1 for p in active_players if p["cur_answer"] is not None)
            time_up = (now - room["question_started_at"]) >= room["time_limit_sec"]
            all_answered = total > 0 and answered >= total
            if not (time_up or all_answered):
                return
            room["state"] = "reveal"
            room["reveal_started_at"] = now
        elif room["state"] == "reveal":
            if now - room["reveal_started_at"] < QUIZ_REVEAL_DURATION_SEC:
                return
            is_last_question = room["current_q"] + 1 >= len(room["questions"])
            room["reveal_started_at"] = None
            room["first_correct_id"] = None
            room["first_correct_nickname"] = None
            for p in room["players"].values():
                p["cur_answer"] = None
                p["cur_correct"] = None
                p["cur_answered_at"] = None
            if is_last_question:
                room["state"] = "ended"
                room["ended_at"] = now
                _archive_room_if_needed(room)
                return
            question_number = room["current_q"] + 1  # 1-indexed
            if question_number % QUIZ_RANKING_INTERVAL == 0:
                room["state"] = "ranking"
                room["ranking_started_at"] = now
            else:
                room["current_q"] += 1
                room["state"] = "intro"
                room["intro_started_at"] = now
                room["question_started_at"] = None
        elif room["state"] == "ranking":
            if now - room["ranking_started_at"] < QUIZ_RANKING_DURATION_SEC:
                return
            room["ranking_started_at"] = None
            room["current_q"] += 1
            room["state"] = "intro"
            room["intro_started_at"] = now
            room["question_started_at"] = None
        else:
            return
```
- これが、コメントで説明されている状態遷移を、**そのまま実装したコード**です。`while True:`で囲まれている理由がコメントにあります：「次の問題もすぐ制限時間切れ…という極端なケースは無いはずだが、万一に備えてループで再評価する」。つまり、1回の呼び出しで**複数段階の遷移が連続して起こりうる**（例えば、サーバーがしばらく呼ばれずに時間だけが経過していた場合、`countdown`→`intro`→`question`のように何段階も一気に進む必要がある）ため、`while`ループで「これ以上進める段階が無くなるまで」繰り返し評価しています。各`elif`ブロックの最後で`return`せず次の`while`の周回に進む（＝`state`を書き換えるだけで`continue`相当の動きになる）ことで、この「連続遷移」が実現されています。
- `"question"`から`"reveal"`への遷移条件`time_up or all_answered`… 制限時間が来たか、**全員が回答し終わった**かのどちらかです。全員が早く答え終われば、制限時間いっぱいまで待たずにすぐ次に進む、という気の利いた挙動です。`active_players`で絞り込んでいるのは、途中参加でまだこの問題に混ざれない「見学中」の人を、全員回答済み判定から除外するためです（見学中の人は回答できないので、含めてしまうと永遠に「全員回答済み」にならず、制限時間いっぱい待たされてしまいます）。
- **`"reveal"`から次への遷移（★ 追加：`"ranking"`を挟むようになった）**：最終問題の発表後だけは直接`"ended"`にし、`_archive_room_if_needed`（後の章で解説）を呼びます。そうでなければ、今revealし終えた問題の番号（1-indexed）が`QUIZ_RANKING_INTERVAL`（5）の倍数のとき（5問目・10問目…）だけ`"ranking"`（スコア順の途中経過。フロント側でKahoot風に順位変動をアニメーションさせる）を挟み、それ以外の問題の発表後は`"ranking"`を飛ばして`current_q`を1つ進め直接次の問題の`"intro"`へ進みます（後者は下の`"ranking"`分岐と同じ後始末をこの場でまとめて行っている形です）。`cur_answer`/`cur_correct`/`cur_answered_at`のリセットは、以前は`"reveal"`→`"intro"`の遷移時（＝次の問題の直前）にまとめて行っていましたが、`"ranking"`画面はこれらの値を使わない（スコアだけを見せる）ため、`"reveal"`を抜ける時点で先にリセットするよう変更されています。
- `"ranking"`から次への遷移：`QUIZ_RANKING_DURATION_SEC`秒経ったら`current_q`を1つ進めて`"intro"`に戻ります（次の問題の「第N問」表示）。

## 4. 専用の監視スレッド：`_quiz_scheduler_loop`（4814〜4850行）

```python
QUIZ_SCHEDULER_TICK_SEC = 0.15

def _quiz_scheduler_loop():
    """
    ★ 以前は「誰かがAPI（ポーリング等）を呼んだ瞬間にだけ」時間切れを
      チェックしていたため、次に誰かがポーリングするまで状態の切り替わりが
      遅れていた（ポーリング間隔ぶんの遅延）。
      この専用スレッドが誰のリクエストも待たずに一定間隔で全部屋を自動的に
      チェックし、状態が変わった瞬間にSSE(notify_change)で全員へ即座に
      知らせることで、「時間になったら勝手に切り替わる」ようにする。
    """
    while True:
        time.sleep(QUIZ_SCHEDULER_TICK_SEC)
        try:
            now = time.time()
            changed_guild_ids = set()
            with QUIZ_ROOMS_LOCK:
                for room in QUIZ_ROOMS.values():
                    state_before = room["state"]
                    _quiz_autoadvance_locked(room, now)
                    if room["state"] != state_before:
                        changed_guild_ids.add(room["guild_id"])
            for guild_id in changed_guild_ids:
                notify_change(guild_id)
        except Exception as e:
            print(f"[ERROR] quiz scheduler tick failed: {e}")

def start_quiz_scheduler():
    Thread(target=_quiz_scheduler_loop, daemon=True).start()
    print("[INFO] Quiz scheduler thread started")
```
- ここに、**時間経過による自動進行の仕組みが、後から改善された経緯**が記されています。以前は`_quiz_autoadvance_locked`が「誰かがAPIを呼んだ瞬間」にしか評価されておらず、例えば制限時間が過ぎても、次に誰かがポーリングでアクセスするまで状態が切り替わらない、という遅延がありました。この`_quiz_scheduler_loop`は、**0.15秒ごとに、誰のリクエストも待たずに全ルームを自動的にチェックする専用スレッド**です。
- `[../01_起動と初期設定/00_設定の読み込みとFlask_Discordの初期化.md](../01_起動と初期設定/00_設定の読み込みとFlask_Discordの初期化.md)`で見たDiscord Bot側の非同期ループ（`AsyncIOScheduler`）とは**完全に別の、独立したスレッド**として動きます。コメントの通り、`QUIZ_ROOMS_LOCK`を握るのは一瞬（軽い辞書走査だけ）なので、Discord側や他のAPIリクエストをブロックする心配はほぼありません。
- `changed_guild_ids`… 状態が実際に変わったルームのguild_idだけを集め、そのguildにだけ`notify_change`します。これにより、変化の無い部屋については何も通知が発生せず、無駄なSSE通知を避けています。
- `except Exception as e: print(...)`… コメントにある通り、1回のチェックで例外が起きてもこのスレッド自体は止めません。もし止まってしまうと、クイズの自動進行がポーリング頼みの、以前の遅延がある方式に逆戻りしてしまいます。**無限ループの中で例外を握りつぶし、次の周回に必ず進む**というこのパターンは、常駐する監視スレッドの定番の書き方です。
