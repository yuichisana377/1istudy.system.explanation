# 設定ファイルと不正文字チェック（`bot.py` 495〜608行）

対象：`bot.py`の「設定ファイル」「入力チェック：制御文字・不可視文字・壊れた符号位置を弾く」セクション。

## 1. サーバー設定ファイル（498〜522行）

```python
def load_config(guild_id: int):
    data, _ = local_get(f"config_{guild_id}.json")
    return data or {}

def save_config(guild_id: int, data: dict):
    _, sha = local_get(f"config_{guild_id}.json")
    local_put(f"config_{guild_id}.json", data, sha)
```
- Discordサーバー（guild）ごとの設定（通知チャンネルの指定など）を`config_{guild_id}.json`に保存・読み込みする、素朴なラッパー関数です。前の回で解説した`local_get`/`local_put`をそのまま使っています。
- `save_config`は、保存前にまず`local_get`で最新のshaを取得し直してから`local_put`に渡しています。これにより「他の誰かが設定を先に書き換えていた場合の排他制御」が効きます。
- `data or {}`… `data`が`None`（ファイルがまだ存在しない、初回アクセス）の場合は、空の辞書`{}`を代わりに返します。呼び出し側は「まだ設定が無い」ことを気にせず、いきなり`config.get("何か")`のような書き方ができます。
- `async_load_config`/`async_save_config`は、[[00_ファイル読み書きとSHA排他制御.md]]で解説した非同期版（`async_local_get`/`async_local_put`）を使った、Discord Bot側のコマンド処理から呼ぶためのバージョンです。

```python
def list_all_configs():
    if not os.path.isdir(DATA_DIR):
        return []
    return [
        name for name in os.listdir(DATA_DIR)
        if name.startswith("config_")
        and name.endswith(".json")
        and os.path.isfile(_data_path(name))
    ]
```
- `DATA_DIR`直下にある、`config_`で始まり`.json`で終わるファイル名だけを一覧取得します。「今まで一度でも設定を保存したことがあるDiscordサーバー全部」を洗い出すのに使われます（自動通知の対象サーバーを1つずつ回るような処理で使われます）。
- リスト内包表記（`[... for ... if ...]`という書き方）で、条件に合う名前だけを1行で集めています。

## 2. 不正文字チェックの仕組み（524〜603行）

コメントにある通り、これは[[../../1I勉強会web解説/02_Cardmaker/00_HTML構造とページ全体像.md]]など、フロント側の解説でも登場した`findBugChars()`/`warnIfBugChars()`（Cardmaker.js側のチェック）と**まったく同じ判定基準を、サーバー側にも独立して実装したもの**です。フロント側のJavaScriptによるチェックは、あくまでブラウザの画面上での親切機能でしかなく、ブラウザの開発者ツール（devtools）などを使えば、フロント側のコードを経由せずに直接APIへリクエストを送りつけることができてしまいます。そのため、「危険な文字を弾く」という最終的な判断は、**必ずサーバー側でも独立して行う必要がある**、というのがこの仕組みの存在理由です（フロント側のチェックは「ユーザーへの親切な事前警告」、サーバー側のチェックは「実際の防御」という役割分担です）。

弾く対象は主に3種類です。
1. 制御文字（右から左に書く言語の表示順序を操作するRLO/LROなどの「双方向制御文字」・見えないテキストを埋め込めるUnicodeタグ文字など）
2. 見た目には何も表示されないが実害の大きい文字（ゼロ幅スペース／Word Joiner／BOMなど）
3. 壊れた符号位置（孤立サロゲート・非文字コードポイント。GitHub等に保存する際にエラーになったり、読み込めなくなったりする原因になります）

逆に、①②③や㈱㈲㈹のような「機種依存文字」（見た目としてちゃんと表示される特殊な文字）は許可されます。

```python
BUG_CHAR_RANGES = [
    (0xE000, 0xF8FF),
    (0xFDD0, 0xFDEF),
]
BUG_CHAR_CODES = {0xFFFE, 0xFFFF}

INVISIBLE_CHAR_RANGES = [
    (0x200B, 0x200C),
    (0x2060, 0x2064),
    (0x2066, 0x2069),
    (0x202A, 0x202E),
    (0xE0000, 0xE007F),
]
INVISIBLE_CHAR_CODES = {0x00AD, 0x180E, 0xFEFF}
```
- これらは全て**Unicodeのコードポイント**（1つ1つの文字に割り振られている番号。`0xE000`のような`0x`から始まる書き方は16進数を表します）の範囲・個別の値のリストです。それぞれのコメント通りの意味を持つ、特殊な制御用・不可視の文字のリストです。「なぜこの文字を弾くのか」を1つずつ完全に理解する必要はありませんが、要は「画面上に何かが表示されるわけでもないのに、テキストの中に紛れ込むと問題を起こしうる文字」を、事前に調べ上げてリストにしてある、と理解しておけば十分です。

```python
def _is_allowed_invisible(cp: int) -> bool:
    if cp == 0x200D:
        return True  # ZWJ（絵文字結合）
    if 0xFE00 <= cp <= 0xFE0F:
        return True  # VS1-16（異体字・絵文字表示指定）
    if 0xE0100 <= cp <= 0xE01EF:
        return True  # VS17-256（IVS用）
    return False
```
- 「見た目には何も表示されない文字」であっても、例外的に許可すべきものがあります。代表的なのが絵文字です。例えば「👨‍👩‍👧‍👦（家族の絵文字）」のような複数人の絵文字が組み合わさった1つの絵文字は、実際には複数の絵文字が「ZWJ（Zero Width Joiner、ゼロ幅結合子）」という見えない文字で繋ぎ合わされて1つに見えるように表示されています。これを弾いてしまうと、生徒が普通に使う絵文字の一部が入力できなくなってしまうため、`_is_allowed_invisible`で明示的に例外扱いにしています。同様に、異体字セレクタ（同じ文字でも微妙に違う字形を指定するもの）や、IVS（絵文字の細かいバリエーション指定）も許可されています。

```python
def find_bug_chars(s):
    if not s:
        return []
    found = []
    for ch in str(s):
        cp = ord(ch)
        if _is_allowed_invisible(cp):
            continue
        is_ctrl = cp < 0x20 and ch not in ("\t", "\n", "\r")
        is_del  = cp == 0x7F
        is_lone_sg = 0xD800 <= cp <= 0xDFFF
        is_range = any(s0 <= cp <= e0 for s0, e0 in BUG_CHAR_RANGES) or cp in BUG_CHAR_CODES
        is_invis = any(s0 <= cp <= e0 for s0, e0 in INVISIBLE_CHAR_RANGES) or cp in INVISIBLE_CHAR_CODES
        if (is_ctrl or is_del or is_lone_sg or is_range or is_invis) and ch not in found:
            found.append(ch)
    return found
```
- 渡された文字列`s`を1文字ずつ調べ、問題のある文字だけを重複なく集めて返す関数です。
- `ord(ch)`… 1文字をそのUnicodeコードポイント（番号）に変換します。
- `_is_allowed_invisible(cp)`に該当すれば（絵文字結合などの許可された不可視文字なら）、その文字は無視して次へ進みます（`continue`）。
- `is_ctrl`… コードポイントが`0x20`（半角スペース）未満、つまり制御文字の範囲にあり、かつタブ・改行・キャリッジリターン（`\t`, `\n`, `\r`。これらは通常の入力で普通に使われるため許可）ではないもの。
- `is_del`… `0x7F`（DEL文字、削除制御文字）。
- `is_lone_sg`… 「孤立サロゲート」の範囲。サロゲートペアとは、絵文字のような番号の大きい文字をUTF-16で表現するために使われる、2つで1組の特殊なコード単位のことです。正しくペアで使われていれば問題ありませんが、片方だけが単独で（孤立して）出現すると、データとして壊れている状態になります。コメントにあるように、Pythonの文字列は内部的には既に正しいUnicodeとして扱われるため通常はここに引っかかりませんが、JSON等、外部から来たデータに紛れ込むケースに備えて、念のため同じチェックをしています。
- `is_range`/`is_invis`… 先ほど定義した`BUG_CHAR_RANGES`/`INVISIBLE_CHAR_RANGES`などのリストに該当するかどうかです。`any(s0 <= cp <= e0 for s0, e0 in ...)`は「いずれかの範囲に入っていればTrue」という意味のPythonのジェネレータ式です。
- これらのいずれか1つでも該当し、かつまだ`found`に入っていなければ（`ch not in found`で重複を防ぐ）、`found`に追加します。

```python
def reject_if_bug_chars(fields: dict):
    for field_name, value in fields.items():
        if value is None:
            continue
        bad = find_bug_chars(value)
        if bad:
            return jsonify({
                "ok": False,
                "error": f"{field_name} に使用できない文字が含まれています（制御文字・不可視文字など）: "
                         + " ".join(bad)
            })
    return None
```
- これが、このあと全てのFlask APIで実際に呼ばれることになる、この章のまとめ役の関数です。
- `fields`は`{"表示用フィールド名": 値}`という辞書で、例えば`reject_if_bug_chars({"内容": content, "科目": subject})`のように呼び出します。
- 各フィールドの値を`find_bug_chars`でチェックし、1つでも問題のある文字が見つかった項目があれば、その場でエラー用のFlaskレスポンス（`jsonify(...)`で作ったJSON形式のエラー）を返します。エラーメッセージには、実際にどの文字が問題だったか（`" ".join(bad)`で見つかった文字を並べたもの）まで含まれます。
- 全フィールドが問題無ければ`None`を返します。
- コメントにある通り、呼び出し側では`err = reject_if_bug_chars(...); if err: return err`という決まった書き方で使います。`err`が`None`でなければ（＝問題があれば）、その場でそのエラーレスポンスをそのまま関数の戻り値として返し、以降の保存処理を実行せずに打ち切ります。このパターンは、これから読んでいくFlask APIの至るところに登場します。
