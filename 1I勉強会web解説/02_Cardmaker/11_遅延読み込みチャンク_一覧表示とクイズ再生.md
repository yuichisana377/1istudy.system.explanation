## 1. `Cardmaker-listview.js`（214行）— 一覧で見る画面

プレイモード選択の「一覧で見る」を選ぶと開く、1問ずつめくる学習画面とは違い、**全カードの問題と答えをまとめてスクロールで見られる**画面です。[[07_Cardmaker.js_その7_学習モードとクイズ再生.md]]で紹介した`openListView()`の本体がここにあります。

### 1.1 画面を開く（24〜40行）
```js

```
- プレイモード選択モーダルで「問題と解答を逆にする」チェックがONだったかを引き継ぎます。
- `studyIsFolder`/`studyDeckId`/`studyFolderId`/`folderPlayDecks`は、この画面専用の変数ではなく、`openPlayMode()`/`openFolderPlayMode()`（[[06_Cardmaker.js_その6_カード編集と学習データ同期.md]]・[[07_Cardmaker.js_その7_学習モードとクイズ再生.md]]）がすでに設定・読み込み済みのものをそのまま流用しています。学習画面と一覧画面は、同じ「今何を対象にプレイ中か」という状態を共有しているわけです。

### 1.3 描画：`renderListView()`（70〜198行）

この関数は、これまでのCardMakerの中でも珍しく、**すべて`document.createElement`によるDOM API組み立て**で作られています（`innerHTML`へのテンプレート文字列の流し込みをほぼ使っていません）。

```js

setMathText(qEl, qText);
```

- 番号・（フォルダ表示なら）元のデッキ名タグ・「わからない」バッジ・編集ボタン・問題文・問題の画像・解答・解答の画像・（あれば）解説、という多くの部品を、1つずつ`createElement`で作って`appendChild`で積み上げています。徹底してDOM APIで組み立てているのは、この画面が扱うデータ（問題文・解答・画像）がすべて「他の人が作ったカードかもしれない」ユーザー入力だからだと考えられます（[[08_Cardmaker.js_その8_画像処理と基盤機能.md]]の`renderImgList`と同じ安全性の考え方）。
- `item.dataset.key = cardKey(c)`：各カードのブロックに、そのカードを一意に識別するキーを目印として付けておきます。これは1.4節のスクロール機能で使われます。

## 2. `Cardmaker-quizplay.js`（229行）— 一人用選択式クイズ

「クイズ過去問」フォルダのデッキや、自作の多肢選択デッキを、一人で4択（〜5択）クイズとして遊ぶ機能です。コメントに、このデータがどこから来るかの背景が書かれています：「みんなでクイズ」（`Quiz.js`）でホストが作ったオリジナルクイズは、Bot側で自動的に「クイズ過去問」フォルダへアーカイブされ（各問題が`choices`/`correct_indices`を持つデッキとして）、ユーザーが自分でCardMakerに作った多肢選択デッキも同じデータ形式なので、まったく同じこの画面で遊べる、という共通化がされています。ライブのオンライン対戦ルームには接続せず、この画面の中だけで完結する一人用モードです。

### 2.1 クイズの開始：`startSoloQuiz(deckId)`（29〜76行）
```js
await waitForPendingSync(deckId);
let result = await ensureDeckCardsLoaded(deckId, true);
while (!result.ok) { ... }
```
- ここでもCardMaker全体で徹底されている「保留中の同期を待つ→強制的に最新カードを取得、失敗時は再試行できる」というパターンが守られています。

```js
const playable = freshDeck.cards
  .filter(c => Array.isArray(c.choices) && c.choices.length >= CHOICE_MIN)
  .map(c => ({
    ...c,
    correct_indices: Array.isArray(c.correct_indices) ? c.correct_indices
      : (typeof c.correct_index === 'number' ? [c.correct_index] : []),
  }))
  .filter(c => c.correct_indices.length >= 1);
if (!playable.length) {
  await showCmAlert({ title: '選択式の問題がありません', ... });
  return;
}
```
- デッキの中から「選択肢を持つ問題」だけを抽出します。ここでもコメントに「4択固定だったのを2〜5択に一般化。旧形式（`correct_index`単数）のカードも`correct_indices`（配列）へ正規化してから使う」という過去の改修が記録されています。正規化の際、`{...c, ...}`（スプレッド構文でカードのコピーを作る）としているのは、**元のカードオブジェクトを直接書き換えない**ための配慮です。

```js
soloQuizCards  = [...playable];
for (let i = soloQuizCards.length - 1; i > 0; i--) {
  const j = Math.floor(Math.random() * (i + 1));
  [soloQuizCards[i], soloQuizCards[j]] = [soloQuizCards[j], soloQuizCards[i]];
}
```
- [[07_Cardmaker.js_その7_学習モードとクイズ再生.md]]の`shuffleStudy()`と同じFisher-Yatesシャッフルで、出題順をランダムにします。

- 選択肢のボタン自体は先に空の`<span>`だけを含む形で組み立て（`onclick`属性の中身は数値`i`のみで、ユーザー入力は含まれないため安全）、そのあとで`setMathText`を使って選択肢の中身（数式を含みうる、他人が作った可能性のあるデータ）を安全に描画する、という2段階の組み立てになっています。

- スコアの送信（`quiz_archive_submit_score`）が失敗しても、コメントにある通り**ランキングの取得は別途試みます**。2つの通信を別々の`try/catch`で囲むことで、片方が失敗してももう片方の結果は表示できるようにしています。

```js
function renderQuizLeaderboard(rows, myStudentId) {
  const myRank = rows.findIndex(r => r.student_id === myStudentId) + 1;
  document.getElementById('qp-result-rank').textContent =
    myRank > 0 ? `あなたの順位：${myRank} 位 / ${rows.length} 人中` : '';
  document.getElementById('qp-leaderboard').innerHTML = rows.map((r, i) => `
    <div class="qp-lb-row${r.student_id === myStudentId ? ' me' : ''}">
      <span class="qp-lb-rank">${i + 1}</span>
      <span class="qp-lb-name">${esc(r.nickname)}</span>
      <span class="qp-lb-score">${r.score} / ${r.total}</span>
    </div>`).join('');
}
```
- サーバーから返ってきた順位表（`rows`、すでに順位順に並んでいる前提）の中から、自分の学籍番号と一致する行を探して`myRank`（自分の順位）を計算します。`findIndex`は「見つからなければ`-1`」を返すため、`+1`しても`0`になり、`myRank > 0`のチェックで「自分の記録がまだ無い（＝ランキングに載っていない）」ケースを正しく除外できます。
- 自分の行だけ`me`という特別なクラスを付けて、見た目でハイライトできるようにしています。

## まとめ

以上で、`Cardmaker.html`本体・`Cardmaker.js`（9パート）・5つの遅延読み込みチャンクすべての解説が完了しました。CardMaker全体を通じて繰り返し出てきた設計上の考え方を、最後に振り返っておきます。

- **キャッシュを先に見せて、あとから本物のデータで置き換える**（`localStorage`優先表示 → サーバーから最新化）。
- **非同期処理のあとは、待っている間に状態が変わっているかもしれないので、古い参照を信用せず必ず最新の状態から探し直す**（`decks = loadDecks()`のやり直しパターン）。
- **サーバーへの同期は裏で順番待ちの列に並べ、強制的な再取得の直前だけそれを待つ**（`queueSyncDeckToServer`/`waitForPendingSync`）。
- **ユーザー入力を扱う描画は`esc()`か`document.createElement`で安全に組み立て、固定文字列（アイコン等）だけは`innerHTML`を使う**、という一貫した使い分け。
- **重い機能は最初から読み込まず、必要になってから／裏で少しずつ読み込む**（遅延読み込みチャンク）。
- **1回の失敗で行き止まりにせず、常にユーザーが選べる回復手段（再試行・空のまま続行・ローカルのみ保存など）を用意する**。

他ページも同じ形式でこのあと解説していきます。
