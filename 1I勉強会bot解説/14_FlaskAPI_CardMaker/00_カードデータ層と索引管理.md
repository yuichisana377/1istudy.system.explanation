## 2. 運用ログ用の差分生成（4117〜4271行）

コメントにある通り、この一連の関数群は、運用ログの詳細表示を**実際のGitHubのコミット画面**（変更されたファイル名 → `+`/`-`の行差分）にできるだけ近づけたい、という要望から作られています。JSONファイルの中身をそのまま出すのではなく、`true`/`false`・`null`・内部IDのような分かりにくい値を日本語の言葉に置き換えてから（例：`incomplete=true` → `"未完成（作成中）"`）比較することで、「その項目が変わった行だけ」が`-`と`+`の2行で浮かび上がるようになっています。

```python
def _clip_text(s, max_len=150):
    s = (s or "").strip().replace("\n", " ")
    return s if len(s) <= max_len else s[:max_len] + "…"

def _image_count_text(imgs):
    n = len(imgs) if isinstance(imgs, list) else 0
    return f"{n}枚" if n else "(なし)"
```

- `_clip_text`… 問題文・解答などの長いテキストを、改行を除去した上で150文字に切り詰めます。運用ログの1行の表示が長大にならないようにするためです。
- `_image_count_text`… 画像そのもの（base64エンコードされた大きなデータ）はログに出すには大きすぎるため、コメントの通り実データではなく**枚数だけ**を表示します。

- これは[[../03_予定と時間割データ層/00_予定データとログ記録.md]]の`_diff_study_logs`で見たのと**全く同じ教訓**が、より詳しく説明されています。コメントの通り、この不具合修正が実は先にこの`_diff_deck_cards`で発見・修正され、後から勉強ログの同種の不具合（`_diff_study_logs`）にも同じ考え方が横展開された、という順序関係にあります（両方のコメントを読み比べると、この関数の教訓が他の場所にも応用されていく様子が分かります）。
- カードには`id`という安定した識別子（Cardmaker.js側で発行される）があるため、`_study_log_key`の`time`のような代用ではなく、**専用のIDによる突き合わせ**ができます。処理は3段階です。

  2. 古い方にだけあるキー → 削除されたカード（`-`）。

## 4. 行単位のテキスト差分：`_text_diff_lines`（4256〜4271行）

```python
def _text_diff_lines(old_text, new_text, max_lines=60):
    old_lines = (old_text or "").splitlines()
    new_lines = (new_text or "").splitlines()
    out = [
        l for l in difflib.ndiff(old_lines, new_lines)
        if l.startswith("+ ") or l.startswith("- ")
    ]
    if not out:
        return None
    if len(out) > max_lines:
        out = out[:max_lines] + [f"…ほか{len(out) - max_lines}行"]
    return "\n".join(out)
```
- これが、これまで何度も名前が登場していた、**運用ログのdiff機能の最も基礎となる関数**です。Pythonの標準ライブラリ`difflib`の`ndiff`関数で、2つのテキストを行単位で比較します。`ndiff`は本来、変化の無い行にも`  `（先頭に空白2つ）のような印を付けて全行を返しますが、`if l.startswith("+ ") or l.startswith("- ")`で、**変化があった行だけ**（追加は`+ `、削除は`- `で始まる行）に絞り込んでいます。
- コメントにある通り、変化が無ければ`None`を返し、呼び出し側はこれを見て運用ログに何も表示しません（分からない/変化していないものを無理に表示しない、というシンプルな方針です）。
